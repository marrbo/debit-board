# 📦 DataTable Independente — Roadmap de Evolução

> **Objetivo:** Transformar o `DataTable` atual em um pacote open source independente (`@debit-board/data-table`), com API pública estável, documentação, testes e exemplos interativos.
>
> **Estratégia:** Evoluir incrementalmente em 4 fases, sem reescrever o que já funciona. Cada fase entrega valor utilizável internamente antes de avançar para a próxima.

---

## 🗺️ Visão Macro das Fases

| Fase  | Nome                       | Foco                                  | Duração estimada |
| ----- | -------------------------- | ------------------------------------- | ---------------- |
| **1** | Funcionalidades Essenciais | Paridade competitiva + acessibilidade | 2-3 sprints      |
| **2** | Melhorias de UX            | Refinamento de triagem e workflow     | 2 sprints        |
| **3** | Empacotamento              | Extração, testes, docs, publicação    | 2-3 sprints      |
| **4** | Recursos Avançados         | Diferenciais e escala                 | Contínuo         |

## 🏃 Fase 1 — Funcionalidades Essenciais

### 🎯 Objetivo

Alcançar paridade funcional com as principais bibliotecas do mercado (TanStack Table, react-data-table-component) **mantendo** nossos diferenciais (modo cards, PDF vetorial, DBQL, ações em lote).

### 📋 Backlog

| #   | Item                             | Prioridade | Complexidade | Status |
| --- | -------------------------------- | ---------- | ------------ | ------ |
| 1.1 | Expandable Rows                  | Alta       | Média        | ⬜     |
| 1.2 | Acessibilidade (ARIA + Keyboard) | Alta       | Média        | ⬜     |
| 1.3 | Sticky Header                    | Alta       | Baixa        | ⬜     |
| 1.4 | Sticky Footer (Pagination)       | Média      | Baixa        | ⬜     |
| 1.5 | Inline Editing com validação     | Média      | Alta         | ⬜     |

### 📌 Detalhamento

#### 1.1 — Expandable Rows

- **Descrição:** permitir que uma linha se expanda revelando um painel com conteúdo customizado.
- **Props previstas:**
  - `expandableRows?: boolean`
  - `renderExpandedRow?: (item: T) => React.ReactNode`
  - `expandOnRowClick?: boolean` (default `false`)
- **Critérios de aceite:**
  - Ícone de chevron animado (rotate 90°) na primeira coluna
  - Apenas uma linha expandida por vez (configurável)
  - Estado de expansão preservado durante refetch
- **Referência visual:** react-data-table-component `expandableRows`

#### 1.2 — Acessibilidade (WCAG 2.1 AA)

- **Descrição:** tornar o DataTable utilizável por leitores de tela e navegação por teclado.
- **Escopo:**
  - `role="grid"`, `role="row"`, `role="columnheader"`, `role="gridcell"`
  - `aria-sort` nas colunas ordenáveis (`ascending` / `descending` / `none`)
  - `aria-selected` nas linhas selecionáveis
  - `aria-rowcount` / `aria-colcount` no container
  - Keyboard navigation: setas para navegar, `Enter` para expandir/selecionar, `Space` para checkbox
  - Focus trap quando expandable rows estão abertas
- **Critérios de aceite:**
  - Auditoria com Lighthouse > 95 em acessibilidade
  - Teste manual com NVDA/VoiceOver
- **Referência:** TanStack Table a11y guide

#### 1.3 — Sticky Header

- **Descrição:** fixar o `<thead>` no topo do container durante scroll vertical.
- **Props previstas:**
  - `stickyHeader?: boolean` (default `false`)
  - `stickyHeaderOffset?: number` (para compensar headers da app)
  - `maxHeight?: string | number` (altura máxima do container)
- **Critérios de aceite:**
  - Funciona em conjunto com o overlay de loading existente
  - Não conflita com o `headerHeight` já calculado via `useLayoutEffect`
  - Compatível com `table-layout: fixed` e `auto`
- **Impacto:** alto — melhora leitura de tabelas longas

#### 1.4 — Sticky Footer (Pagination)

- **Descrição:** fixar a barra de paginação no rodapé do container.
- **Props previstas:**
  - `stickyFooter?: boolean` (default `false`)
  - Reaproveita `stickyHeaderOffset` para alinhamento
- **Critérios de aceite:**
  - Não sobrepõe a última linha da tabela
  - Animação suave ao aparecer/sumir em scroll
  - Container deve ter altura máxima definida para funcionar
- **Impacto:** médio — melhora UX em viewports pequenas

#### 1.5 — Inline Editing com validação

- **Descrição:** editar células diretamente na tabela com validação e persistência.
- **Props previstas:**
  - `editable?: (item: T) => boolean`
  - `onCellEdit?: (item: T, key: string, newValue: any) => Promise<void>`
  - `validateCell?: (value: any, item: T) => string | null` (retorna mensagem de erro)
- **Critérios de aceite:**
  - Duplo clique para entrar em modo de edição
  - `Enter` confirma, `Esc` cancela
  - Estado de salvamento (loading) por célula
  - Rollback visual em caso de erro
  - Compatível com todos os tipos de coluna (`render`, badges, etc.)
- **Complexidade:** alta — envolve gerenciamento de estado por célula
- **Prioridade:** média (depende de demanda real)

## 🏃 Fase 2 — Melhorias de UX

### 🎯 Objetivo

Refinar a experiência de triagem do analista de segurança, incorporando as demandas das Sprints 1, 2 e 3 do roadmap de UI (badges de severidade, ações rápidas, persistência de estado).

### 📋 Backlog

| #   | Item                                              | Prioridade | Complexidade | Status |
| --- | ------------------------------------------------- | ---------- | ------------ | ------ |
| 2.1 | Badges de Severidade componentizados              | Alta       | Baixa        | ⬜     |
| 2.2 | Borda esquerda colorida por severidade            | Média      | Baixa        | ⬜     |
| 2.3 | Hover Actions (ações rápidas por linha)           | Alta       | Média        | ⬜     |
| 2.4 | Ícone de Origem (Source Integration)              | Média      | Baixa        | ⬜     |
| 2.5 | Persistência de Filtros e Scroll (`useGridState`) | Alta       | Média        | ⬜     |

### 📌 Detalhamento

#### 2.1 — Badges de Severidade

- **Descrição:** componente reutilizável `<SeverityBadge severity="..." />` para uso em tabelas, cards e modais.
- **Variantes:**
  - `default`: fundo colorido suave + texto escuro + ícone circular (ideal para tabela)
  - `compact`: apenas ícone + texto curto (C/H/M/L) para espaços apertados
  - `outline`: borda colorida + fundo transparente (para modais)
- **Design system:**
  - `critical`: `bg-red-100 text-red-700 border-red-300` + ícone `AlertOctagon`
  - `high`: `bg-orange-100 text-orange-700 border-orange-300` + ícone `AlertTriangle`
  - `medium`: `bg-yellow-100 text-yellow-800 border-yellow-300` + ícone `Circle`
  - `low`: `bg-blue-100 text-blue-700 border-blue-300` + ícone `Circle`
- **Tipografia:** `text-xs font-semibold tracking-wide uppercase`
- **Critérios de aceite:** contraste WCAG AAA em tema claro e escuro

#### 2.2 — Borda Esquerda Colorida por Severidade

- **Descrição:** linha ganha filete vertical de 3px colorido por severidade no hover.
- **Props previstas:**
  - `rowAccent?: (item: T) => string | null` (retorna cor CSS ou classe)
- **Critérios de aceite:**
  - Funciona em conjunto com zebra striping existente
  - Transição suave de 150ms
  - Não desloca o conteúdo (usar `border-l-[3px]` com `box-sizing: border-box`)

#### 2.3 — Hover Actions

- **Descrição:** ações rápidas reveladas ao passar o mouse sobre a linha.
- **Props previstas:**
  - `quickActions?: (item: T) => DataTableAction<T>[]`
- **Ações padrão do Debit-Board:**
  - Marcar como resolvido (`CheckCircle`)
  - Atribuir responsável (`UserPlus`)
  - Abrir no repositório (`ExternalLink`)
- **Critérios de aceite:**
  - Botões ocultos (`opacity-0`) por padrão
  - Revelados em `group-hover:opacity-100` com `transition-opacity`
  - Tooltips flutuantes curtos (usar `title` nativo ou um `<Tooltip />` do design system)
  - Área de toque mínima de 32×32px

#### 2.4 — Ícone de Origem (Source Integration)

- **Descrição:** coluna padronizada com ícone + nome truncado da ferramenta que detectou a vulnerabilidade.
- **Mapa de fontes suportadas:**
  - SonarQube, Trivy, Dependabot, Azure DevOps, Snyk, Semgrep, CodeQL
- **Props previstas:**
  - `sourceMap?: Record<string, { icon: ReactNode; color: string }>`
- **Critérios de aceite:**
  - Ícone 16×16px
  - Nome em `text-xs text-slate-500`
  - Truncamento com `title` nativo para nomes longos

#### 2.5 — Persistência de Estado (`useGridState`)

- **Descrição:** hook unificado que preserva filtros, página e scroll entre navegações.
- **API do hook:**
  ```ts
  const { state, setFilter, setPage, setScroll, reset } = useGridState(
    "observations",
    {
      persist: "sessionStorage", // ou "url" para searchParams
      filters: ["severity", "status", "source"],
    },
  );
  ```
- **Estados preservados:**
  - Filtros ativos (severity, status, source, etc.)
  - Página atual
  - Densidade de itens (`pageSize`)
  - Posição do scroll vertical em pixels
  - Modo de visualização (tabela/cards)
- **Critérios de aceite:**
  - Restauração do scroll após o primeiro render (usar `useLayoutEffect`)
  - Limpeza automática ao fazer logout
  - Não conflita com o `storageKey` atual do `DataTable` (migrar para o hook)

## 🏃 Fase 3 — Empacotamento e Publicação

### 🎯 Objetivo

Extrair o `DataTable` e seus utilitários para um pacote independente, com API pública estável, documentação e testes, pronto para publicação no npm.

### 📋 Backlog

| #   | Item                                           | Prioridade | Complexidade | Status |
| --- | ---------------------------------------------- | ---------- | ------------ | ------ |
| 3.1 | Extração para monorepo (`packages/data-table`) | Alta       | Alta         | ⬜     |
| 3.2 | API pública documentada (types + props)        | Alta       | Média        | ⬜     |
| 3.3 | Testes unitários e de integração               | Alta       | Alta         | ⬜     |
| 3.4 | Storybook interativo                           | Alta       | Média        | ⬜     |
| 3.5 | Publicação no npm                              | Alta       | Baixa        | ⬜     |
| 3.6 | CHANGELOG + versionamento semântico            | Média      | Baixa        | ⬜     |

### 📌 Detalhamento

#### 3.1 — Extração para Monorepo

- **Estrutura sugerida:**
  ```
  packages/
    data-table/
      src/
        components/
        hooks/
        types/
        utils/
        index.ts
      package.json
      tsconfig.json
      README.md
  ```
- **Ferramentas recomendadas:**
  - **pnpm workspaces** ou **Turborepo** para gerenciar o monorepo
  - **tsup** ou **unbuild** para bundling (ESM + CJS + types)
- **Dependências peer:**
  - `react`, `react-dom`
  - `tailwindcss` (via preset distribuído)
  - `lucide-react`
  - `@mui/material` (apenas para `ConfirmDialog` — tornar opcional)
- **Critérios de aceite:**
  - App principal importa de `@debit-board/data-table`
  - Build do pacote gera ESM, CJS e `.d.ts`
  - Tree-shaking funcional

#### 3.2 — API Pública Documentada

- **Formato:** README com:
  - Instalação
  - Exemplo mínimo funcional
  - Tabela de props completa
  - Exemplos avançados (modo cards, PDF, expandable rows)
  - Guia de migração (de outras libs)
- **Tipos exportados:**
  - `DataTableProps<T>`, `Column<T>`, `DataTableAction<T>`
  - `ExportOptions`, `ExportFilters`
  - `TableToolbarProps`, `TablePaginationProps`
- **Critérios de aceite:**
  - Um novo usuário consegue renderizar uma tabela simples em < 5 minutos

#### 3.3 — Testes

- **Stack:** Vitest + Testing Library + `@testing-library/user-event`
- **Cobertura mínima:** 80%
- **Casos críticos:**
  - Sorting tri-state (asc → desc → none)
  - Selection com `rowSelectable`
  - Paginação + mudança de pageSize
  - Fetch com cancelamento (`AbortController`)
  - Exportação PDF (mock do jsPDF)
  - Persistência de viewMode
- **Critérios de aceite:**
  - CI roda testes em cada PR
  - Snapshot tests para componentes visuais

#### 3.4 — Storybook

- **Histórias essenciais:**
  - Tabela básica (5 colunas, 10 linhas)
  - Tabela com seleção e ações em lote
  - Modo cards
  - Estados de loading/empty/error
  - Expandable rows
  - Tema claro/escuro
- **Critérios de aceite:**
  - Storybook publicado no Chromatic ou Vercel
  - Cada prop documentada via `argTypes`

#### 3.5 — Publicação no npm

- **Nome do pacote:** `@debit-board/data-table`
- **Acesso:** público (`--access public`)
- **Pipeline:** GitHub Actions com:
  - `npm test`
  - `npm run build`
  - `npm publish` (apenas em tags `v*`)
- **Critérios de aceite:**
  - Instalação via `npm install @debit-board/data-table` funciona em projeto novo

#### 3.6 — CHANGELOG + Versionamento

- **Ferramenta:** `changesets` (recomendado)
- **Convenção:** [Keep a Changelog](https://keepachangelog.com/)
- **Critérios de aceite:**
  - CHANGELOG gerado automaticamente em cada release
  - SemVer rigoroso (breaking changes em major)

## 🏃 Fase 4 — Recursos Avançados

### 🎯 Objetivo

Adicionar diferenciais competitivos que posicionam o pacote como referência para dashboards de segurança.

### 📋 Backlog

| #   | Item                                          | Prioridade | Complexidade | Status |
| --- | --------------------------------------------- | ---------- | ------------ | ------ |
| 4.1 | Virtualização (`@tanstack/react-virtual`)     | Média      | Alta         | ⬜     |
| 4.2 | Column Resizing                               | Média      | Média        | ⬜     |
| 4.3 | Column Pinning (fixar colunas)                | Média      | Alta         | ⬜     |
| 4.4 | Row Grouping                                  | Baixa      | Alta         | ⬜     |
| 4.5 | Exportação CSV/JSON nativa                    | Baixa      | Baixa        | ⬜     |
| 4.6 | Server-side sorting/filtering helpers         | Média      | Média        | ⬜     |
| 4.7 | Tema distribuído (preset Tailwind + CSS vars) | Alta       | Média        | ⬜     |

### 📌 Detalhamento

#### 4.1 — Virtualização

- **Descrição:** renderizar apenas linhas visíveis em tabelas com > 5.000 registros.
- **Stack:** `@tanstack/react-virtual`
- **Props previstas:**
  - `virtualized?: boolean`
  - `estimateRowHeight?: number`
- **Critérios de aceite:**
  - 10.000 linhas renderizam a 60fps
  - Compatível com sticky header
  - Expandable rows funcionam virtualizadas

#### 4.2 — Column Resizing

- **Descrição:** usuário arrasta a borda da coluna para redimensionar.
- **Props previstas:**
  - `resizableColumns?: boolean`
  - `onColumnResize?: (key: string, width: number) => void`
  - Persistência automática via `useGridState`

#### 4.3 — Column Pinning

- **Descrição:** fixar colunas à esquerda ou direita durante scroll horizontal.
- **Props previstas:**
  - `pinnedColumns?: { left?: string[]; right?: string[] }`
- **Critérios de aceite:**
  - Sombra sutil na borda das colunas fixadas
  - Compatível com sticky header

#### 4.4 — Row Grouping

- **Descrição:** agrupar linhas por valor de coluna (ex.: agrupar observações por severidade).
- **Props previstas:**
  - `groupBy?: string` (chave da coluna)
  - `renderGroupHeader?: (value: any, count: number) => ReactNode`
- **Complexidade:** alta — muda a estrutura de renderização

#### 4.5 — Exportação CSV/JSON

- **Descrição:** hook headless `useTableExport` inspirado no react-data-table-component.
- **API prevista:**
  ```ts
  const { exportCSV, exportJSON } = useTableExport({ columns, data });
  ```
- **Critérios de aceite:**
  - Respeita filtros ativos
  - Compatível com `pdfCellRenderer` (usa texto plano como fallback)

#### 4.6 — Helpers de Server-Side

- **Descrição:** utilitários para facilitar integração com APIs backend.
- **Exemplos:**
  - `buildQueryParams(state)` → gera `URLSearchParams` a partir do estado
  - `parseQueryParams(searchParams)` → hidrata o estado a partir da URL
- **Impacto:** reduz boilerplate em apps Next.js

#### 4.7 — Tema Distribuído

- **Descrição:** preset Tailwind + CSS variables para facilitar customização.
- **Entrega:**
  - `@debit-board/data-table/tailwind-preset`
  - Arquivo `theme.css` com variáveis (`--dt-bg`, `--dt-border`, etc.)
- **Critérios de aceite:**
  - Usuário customiza cores via CSS sem tocar no código do pacote

## 🚫 Não-objetivos (fora de escopo)

- Substituir o DataTable por outra biblioteca (react-data-table-component, TanStack Table) — já avaliamos e decidimos manter o nosso.
- Suporte a React Native ou mobile nativo.
- Suporte a SSR com hidratação parcial (o DataTable é client-side por natureza).
- Persistência em backend (só `sessionStorage` e `URL`).
