# Processo de Gestão de Melhorias e Correção de Bugs

## 1. Introdução
Este documento tem como objetivo centralizar, organizar e priorizar todas as demandas relacionadas à evolução do sistema, abrangendo tanto a correção de inconsistências funcionais (Bugs) quanto a implementação de aprimoramentos técnicos e visuais (Melhorias). A adoção de um fluxo estruturado para registro e acompanhamento destes itens é fundamental para garantir a qualidade do software, a consistência da experiência do usuário e a aderência aos novos padrões de design estabelecidos (Apple Human Interface Guidelines, com suporte nativo aos temas Light e Dark).

A seguir, apresentamos as instruções para utilização deste artefato, o template padrão que deve ser preenchido para cada nova solicitação e o inventário inicial das demandas já mapeadas.

## 2. Instruções Gerais
Para garantir a rastreabilidade e a eficiência na resolução dos itens listados, orientamos que:

1. **Classificação Obrigatória**: Todo registro deve ser classificado como *Bug* (quando o comportamento atual difere do esperado) ou *Melhoria* (quando se propõe uma evolução ou otimização de uma funcionalidade existente).
2. **Agrupamento por Módulo**: Mantenha os itens organizados por módulo ou tela do sistema para facilitar o planejamento do time de desenvolvimento.
3. **Detalhamento Técnico**: Forneça o máximo de informações possível no template, especialmente no campo "Passos para Reproduzir" (para Bugs) ou "Justificativa de Negócio" (para Melhorias).
4. **Priorização**: Utilize a matriz de severidade para classificar a urgência do item (ex: *Crítico*, *Alto*, *Médio*, *Baixo*), considerando o impacto na operação do usuário e na imagem do produto.
5. **Evidências**: Sempre que possível, anexe *prints* ou vídeos que ilustrem o problema ou a sugestão, facilitando o entendimento e a validação posterior.

## 3. Template Padrão para Cadastro de Itens
Utilize o modelo abaixo para incluir novas demandas neste levantamento:

| **Campo** | **Descrição / Exemplo** |
| :--- | :--- |
| **ID** | Sequencial numérico ou código interno (ex: #001) |
| **Título** | Nome claro e objetivo do problema ou melhoria |
| **Tipo** | [ ] Bug <br> [ ] Melhoria |
| **Módulo / Tela** | Nome da funcionalidade e respectiva URL (ex: SAST Scanner - `/sast`) |
| **Descrição Detalhada** | Contexto aprofundado sobre o que está ocorrendo ou o que se propõe a fazer |
| **Passos para Reproduzir (Bug)** / **Justificativa (Melhoria)** | Sequência lógica para replicar o erro <br> *ou* <br> Motivação e benefício esperado com a mudança |
| **Comportamento Atual** | Como o sistema se comporta hoje |
| **Comportamento Esperado** | Como o sistema deveria se comportar após a correção/implementação |
| **Severidade / Prioridade** | Crítico / Alto / Médio / Baixo |
| **Evidências** | Links, *screenshots* ou referências anexadas |
