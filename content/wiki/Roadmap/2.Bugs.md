## 1. Inventário de Itens Mapeados

### 1.1. Bugs de Interface (UI/UX)

#### #001 – Inconsistência de Temas (Light/Dark) na Tela SAST Scanner

| **Campo** | **Detalhamento** |
| :--- | :--- |
| **Título** | Resquícios de CSS fixo (layout preto) quebram a padronização visual no módulo SAST |
| **Tipo** | Bug |
| **Módulo / Tela** | SAST Scanner – Rota `/sast` |
| **Descrição Detalhada** | Durante a fase de pós-execução do scanner, a interface não respeita o novo padrão arquitetônico de estilos baseado no tema dinâmico da Apple (Light & Dark). Foram identificados trechos de CSS legado com estilização fixa (background preto e cores específicas) que sobrescrevem as variáveis de tema, resultando em uma experiência visual fragmentada e inconsistente com o restante da aplicação. |
| **Passos para Reproduzir** | 
1. Acessar a rota `/sast` no navegador. 
2. Executar uma varredura (Scanner).
3. Aguardar a conclusão do processo e observar a interface exibida.
4. Alternar entre os modos Light e Dark nas configurações do sistema. |
| **Comportamento Atual** | Partes específicas da interface mantêm o fundo preto fixo (herdado do layout antigo), ignorando as variáveis CSS referentes ao novo padrão Apple, causando contraste inadequado e poluição visual. |
| **Comportamento Esperado** | Todas as camadas visuais do módulo `/sast` devem responder dinamicamente à alternância entre os temas Light e Dark, utilizando exclusivamente as variáveis e tokens definidos no guia de estilos unificado, garantindo legibilidade e fluidez visual. |
| **Severidade / Prioridade** | Média/Alta (impacta diretamente a percepção de qualidade e a consistência da identidade visual do produto) |
| **Evidências** | (Aguardando anexo de screenshot comparativo entre o layout atual e o esperado) |

### 2. Bugs de Funcionalidade e Exibição de Dados

#### #002 – Erro na exibição da descrição do padrão na aba "Por que isso é um problema?"

| **Campo** | **Detalhamento** |
| :--- | :--- |
| **Título** | Exibição incorreta da descrição do padrão SAST na aba "Por que isso é um problema?" – Módulo Observações |
| **Tipo** | Bug |
| **Módulo / Tela** | Detalhes da Observação – Rota `/observations/[id]` |
| **Descrição Detalhada** | No fluxo de detalhamento de uma observação, a aba "Por que isso é um problema?" tem como objetivo apresentar ao usuário o contexto técnico e os riscos associados à vulnerabilidade detectada, por meio da descrição cadastrada no padrão SAST vinculado. Entretanto, o sistema está ignorando a base de dados do padrão e renderizando um texto *fallback* estático, impossibilitando que o desenvolvedor compreenda a fundo a razão do apontamento sem precisar navegar para outro módulo. |
| **Passos para Reproduzir** | 
1. Acessar a rota `/observations/[id]`, selecionando uma observação que esteja associada a um padrão SAST.
2. Garantir que o padrão vinculado possua uma descrição técnica preenchida no módulo de Padrões SAST.
3. Navegar até a aba intitulada "Por que isso é um problema?".
4. Observar o conteúdo textual renderizado na interface. |
| **Comportamento Atual** | É exibida a mensagem genérica e fixa: *"Não há descrição cadastrada no sistema para este padrão. O administrador pode cadastrar uma recomendação no módulo de Padrões SAST."*, mesmo quando o padrão já possui descrição válida no banco de dados. |
| **Comportamento Esperado** | O sistema deve realizar a consulta ao repositório de Padrões SAST e exibir dinamicamente a descrição específica daquele *pattern*. A mensagem de *fallback* só deverá ser apresentada em casos legítimos onde a base de dados do padrão não contenha informações preenchidas para aquele campo. |
| **Severidade / Prioridade** | Alta – Compromete a capacidade do usuário de entender a vulnerabilidade no ponto de análise, reduzindo a efetividade do code review e forçando fluxos alternativos desnecessários. |
| **Evidências** | (Aguardando *print* da tela exibindo o texto estático vs. o texto cadastrado no módulo de padrões) |


#### #003 – Erro na exibição da recomendação na aba "Como corrigir?"

| **Campo** | **Detalhamento** |
| :--- | :--- |
| **Título** | Exibição incorreta da recomendação (fix) do padrão SAST na aba "Como corrigir?" – Módulo Observações |
| **Tipo** | Bug |
| **Módulo / Tela** | Detalhes da Observação – Rota `/observations/[id]` |
| **Descrição Detalhada** | A aba "Como corrigir?" é um dos recursos de maior valor agregado da ferramenta, pois orienta diretamente o desenvolvedor sobre as ações necessárias para remediar a vulnerabilidade apontada. Atualmente, a aplicação não está recuperando o campo de recomendação do padrão SAST correspondente à *issue* e, em vez disso, exibe um texto *placeholder* estático. Esse comportamento inviabiliza a entrega do conhecimento técnico prático e prejudica a produtividade do time de desenvolvimento. |
| **Passos para Reproduzir** | 
1. Acessar a rota `/observations/[id]` para uma observação com padrão SAST associado.
2. Verificar se o padrão vinculado possui uma recomendação de correção (ex: snippet de código seguro, instruções de *fix*) devidamente cadastrada.
3. Clicar na aba "Como corrigir?" na página de detalhes da observação.
4. Verificar o conteúdo informacional exibido no corpo da aba. |
| **Comportamento Atual** | O sistema exibe a mensagem padronizada e inespecífica: *"Não há recomendação cadastrada no sistema para este padrão. O administrador pode cadastrar uma recomendação no módulo de Padrões SAST."*, desconsiderando completamente as orientações técnicas já inseridas no cadastro do padrão. |
| **Comportamento Esperado** | A tela deve buscar ativamente a recomendação associada ao *pattern* da observação e renderizá-la de forma clara e estruturada (suportando formatação para trechos de código, se aplicável). Apenas na ausência legítima de dados é que a mensagem de *fallback* deve ser exibida, sinalizando corretamente ao administrador a necessidade de complementar o cadastro. |
| **Severidade / Prioridade** | Alta – Além de quebrar a experiência do usuário, o bug retém uma informação crítica para a correção da vulnerabilidade, resultando em retrabalho, aumento do tempo médio de resolução (MTTR) e possível propagação de falhas por falta de orientação adequada. |
| **Evidências** | (Aguardando anexo comparativo entre o *template* atual e os dados esperados provenientes do módulo de Padrões SAST) |


---

**Observação Complementar**: Recomenda-se que a correção dos itens #002 e #003 seja tratada em conjunto, pois ambos compartilham a mesma raiz causal – a falha na injeção de dados provenientes do repositório de Padrões SAST nas abas da visualização de Observações –, otimizando assim o esforço de desenvolvimento e os testes de regressão.
