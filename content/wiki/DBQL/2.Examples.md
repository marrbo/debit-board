# DBQL Exemplos
## Casos de uso

Esta página contém um guia prático com exemplos reais de consultas utilizando a **Debit Board Query Language (DBQL) v2.0**. 

Aqui você aprenderá como aplicar a sintaxe apresentada na [documentação oficial](./Syntax) para realizar buscas precisas por vulnerabilidades e observations no sistema.

---

## 🧭 Como Usar a DBQL

1. **Acesse o Módulo de Issues:** Navegue até a aba **"Issues"** ou utilize a busca global no menu **"Search"**.
2. **Modo Básico:** Digite a propriedade, dois pontos `:` e o valor desejado (ex: `severity:high`).
3. **Modo Avançado:** Utilize o botão **`</>` (Modo Avançado)** para escrever consultas complexas com parênteses, negações e curingas.

> **Dica:** A busca é **case-insensitive**, mas respeita espaços e aspas duplas `" "` para valores compostos.

## 📝 Exemplos por Categoria

### 1. Filtrando por Severidade e Status
| Objetivo | Consulta DBQL |
| :--- | :--- |
| **Vulnerabilidades Críticas** | `severity:critical` |
| **Erros Abertos de Alta Prioridade** | `severity:high AND status:open` |
| **Vulnerabilidades Médias Já Resolvidas** | `severity:medium AND status:resolved` |
| **Todas as Issues, exceto as de Baixa Gravidade** | `!severity:low` |

### 2. Filtrando por Projeto e Repositório
| Objetivo | Consulta DBQL |
| :--- | :--- |
| **Issues apenas do Projeto "GEPIN_AS"** | `project:GEPIN_AS` |
| **Issues do Repositório "backend-api"** | `repository:backend-api` |
| **Projetos de Frontend (que contêm "front")** | `project:*front*` |

### 3. Filtrando por Arquivo e Extensão
| Objetivo | Consulta DBQL |
| :--- | :--- |
| **Issues em arquivos C#** | `fileName:*Controller.cs` |
| **Issues em arquivos de extensão JavaScript** | `fileName:*.js` |

### 4. Filtros Avançados com Lógica Booleana
| Objetivo | Consulta DBQL |
| :--- | :--- |
| **Buscar SQL Injection ou XSS que estão em aberto** | `(category:"SQL Injection" OR category:"Cross-site Scripting") AND status:open` |
| **Excluir a branch "main" e buscar arquivos de Controller** | `!branch:main AND fileName:*Controller.cs` |
| **Issues recorrentes** | `status:recurring` |
| **Issues com status "Won't Fix"** | `status:wont_fix` |

## 🚀 Cenários do Mundo Real

### Cenário 1: Consulta avançada combinando parênteses grudados e negação
Este exemplo demonstra o uso fluído de parênteses sem espaço obrigatório de fechamento (ex: `branch:master)`) unido à negação em bloco via `!`.

```sql
category:"Broken Access Control" AND project:GEPIN_AS AND (branch:main OR branch:master) AND !(fileName:Auth*.cs OR filePath:*Template*)
```
*Interpretação:* Filtra a categoria exata no projeto `GEPIN_AS`, restringe às branches principais (permitindo parênteses colados) e exclui via operador unário `!` os arquivos de autenticação ou templates.

### Cenário 2: Investigando Injeções de SQL abertas em Controllers
```sql
category:"SQL Injection" AND fileName:*Controller.cs AND status:open
```

## 💡 Dicas e Boas Práticas

- **Fluidez na digitação**: Agora você pode fechar parênteses logo após os valores (ex: `branch:main)`) sem se preocupar com espaços extras.
- **Negações complexas**: Utilize `!(cond1 OR cond2)` para excluir subgrupos inteiros com facilidade.
- **Mantenha os status oficiais**: Lembre-se que os status válidos suportados são `new`, `open`, `resolved`, `recurring` e `wont_fix`.
