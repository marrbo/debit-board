## 🚀 Visão Geral

Esta versão foca em **usabilidade e persistência de busca**, além de melhorias na exportação de dados. Foram implementadas as seguintes funcionalidades e correções:

1. **Botão de Exportação Split** (PDF/Excel) – substitui os botões separados por um único botão com menu dropdown.
2. **Ocultar/Mostrar Busca DBQL** – botão sutil no canto superior direito da barra de busca para minimizar/maximizar o campo.
3. **Persistência de Query Ativa entre Páginas** – ao navegar entre Observações e Stats, a consulta salva é restaurada automaticamente (respeitando o contexto) e aplicada sem necessidade de clicar em "Executar".
4. **Correção de aplicação de filtros** – ao carregar uma saved-query, os dados são filtrados corretamente, mesmo ao alternar de página.
5. **Otimização de `useEffect`** nas páginas de Observações e Stats para evitar chamadas redundantes e garantir que a busca seja disparada quando necessário.
6. **Ajustes na API `/api/stats`** para combinar filtros de forma segura (`$and`) e preservar o `tenantId`.

---

## ✨ Novas Funcionalidades

### 1. ExportSplitButton (Split Button)

- **Descrição:** Os botões "Exportar PDF" e "Exportar Excel" foram unificados em um único componente reutilizável.
- **Comportamento:**
  - O botão principal executa **Exportar PDF**.
  - O chevron ao lado abre um dropdown com as opções **PDF** e **Excel**.
  - Clicar em qualquer opção do dropdown executa a exportação correspondente.
- **Benefício:** Interface mais limpa e menos poluída, além de reduzir duplicação de código.

### 2. Ocultar/Mostrar Busca DBQL

- **Descrição:** Adicionado um botão flutuante (ícone de chevron) no canto superior direito do `DBQLAdvancedSearch`.
- **Comportamento:**
  - Quando a busca está visível, o ícone `ChevronUp` permite minimizar.
  - Quando minimizada, um container compacto com o texto "DBQL Advanced Search" é exibido, mantendo o botão acessível.
  - O clique alterna a visibilidade.
- **Benefício:** Permite ao usuário ocultar a barra de busca para aproveitar mais espaço na tela, sem perder a funcionalidade.

### 3. Persistência de Query Ativa entre Páginas

- **Descrição:** A query ativa (saved-query) agora é armazenada no `sessionStorage` juntamente com o contexto (`observations`, `stats`, etc.).
- **Comportamento:**
  - Ao navegar de uma página para outra, o `DBQLAdvancedSearch` verifica se a query salva pertence ao contexto atual.
  - Se o contexto for o mesmo, a query é restaurada, o texto é preenchido e **a busca é executada automaticamente** (sem precisar clicar em "Executar").
  - Se o contexto for diferente, os campos são limpos e a busca é resetada.
  - A URL também é sincronizada (`?q=<id>` e `?m=a` se avançado) para manter o estado.
- **Benefício:** Elimina a necessidade de reaplicar filtros manualmente ao alternar entre telas, melhorando a fluidez.

## 🛠 Detalhes de Implementação

### Frontend

#### `components/ExportSplitButton.tsx` (novo)

- Componente reutilizável com estado interno de menu.
- Recebe props `onExportPDF` e `onExportExcel`.
- Possui `useEffect` para fechar o menu ao clicar fora.

#### `components/dbql/DBQLAdvancedSearch.tsx`

- Adicionado estado `isSearchVisible` para controlar a visibilidade da busca.
- Botão flutuante (`absolute top-1.5 right-1.5`) com ícone dinâmico.
- Persistência da query ativa:
  - Chave do `sessionStorage` agora inclui `context`.
  - Restauração verifica `source.context === context` (com fallback para `!source.context`).
  - Chamada automática de `onSearch` após restaurar.
- Busca de saved-query por ID (`/api/saved-queries?id=...`) independente do contexto da lista.
- Melhor extração do objeto retornado pela API (trata objeto, array, `{data}`).

#### `app/observations/page.tsx` e `app/stats/page.tsx`

- Substituído uso de `externalQuery`/`onExternalQueryChange` por `onSearch` direto.
- Refatoração dos `useEffect` para buscar dados somente quando necessário.
- Adicionado `lastSearchQueryRef` para evitar buscas duplicadas.
- `handleSearch` atualiza o estado e a ref.

### Backend

#### `app/api/stats/route.ts`

- Alterado para combinar filtros com `$and` (garantindo que `tenantId` e outros filtros sejam preservados).
- Aplicação segura de `parseSearchQuery(searchQuery, {})` para evitar sobrescrita de `tenantId`.

## ⚠️ Considerações e Limitações ( Sugestões de Backlog )

- **Compatibilidade com queries antigas no `sessionStorage`:**  
  Se uma query foi salva antes desta versão (sem campo `context`), ela será restaurada por padrão (fallback `!source.context`). Isso pode ser ajustado no futuro se desejado.

- **Múltiplas chamadas de `onSearch`:**  
  Em alguns cenários, `onSearch` pode ser chamado mais de uma vez (ex: restauração e sincronização). Isso é inofensivo, mas pode ser otimizado com uma flag de inicialização.

- **API `/api/stats`:**  
  A combinação com `$and` funciona, mas é necessário garantir que `parseSearchQuery` suporte todos os operadores DBQL (not `!`, curinga `*`, etc.). Se não suportar, o filtro pode ser ignorado. Recomenda-se validar a função.
