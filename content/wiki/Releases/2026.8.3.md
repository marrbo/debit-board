# Debit Board - Release Notes

**Versão:** v2026.8.3  
**Data de Lançamento:** 22 de agosto de 2026

## 🚀 Visão Geral

Esta versão introduz melhorias significativas na tela de **Stats & Usage**, focando em interatividade, visualização de dados e usabilidade. Foram implementadas quatro novas funcionalidades:

1. **Total por Projeto (TOP 10):** Alternância entre visualização por **Severidade** e por **Status** através de um **slider customizado**, com barras empilhadas e cores dinâmicas.
2. **Evolução de Ocorrências:** Adição de linha de **média móvel (mediana)** e **alternância entre visualização por Severidade ou Status**, com pontos marcantes por data de scan.
3. **Distribuição por Categoria:** Clique em uma fatia do gráfico de pizza para **adicionar automaticamente um filtro DBQL** (`category:"..."`), com opção de limpar o filtro e restaurar a consulta original.
4. **Expandir Gráficos:** Todos os cards de gráficos agora possuem um ícone de expandir (tela cheia) que abre um modal com o gráfico em tamanho maior, mantendo o contexto da página.

Todas as melhorias foram desenvolvidas mantendo a estética e usabilidade padrão visual clean, minimalista, com feedback visual imediato.

## ✨ Novas Funcionalidades

### 1. Slider de Visualização no Gráfico "Total por Projeto (TOP 10)"

- **Descrição:** O card agora exibe um controle deslizante (estilo iOS) que permite alternar entre visualizar as issues agrupadas por **Severidade** (Crítico, Alto, Médio, Baixo) ou por **Status** (Aberto, Recorrente, Resolvido, Não Corrigir).
- **Comportamento:**
  - As barras são **empilhadas** (stacked bar) para mostrar a composição de cada projeto.
  - As cores seguem o padrão visual já utilizado no sistema:
    - **Severidade:** Crítico (vermelho), Alto (laranja), Médio (amarelo), Baixo (azul).
    - **Status:** Aberto (azul), Recorrente (laranja), Resolvido (verde), Não Corrigir (cinza).
- **Benefício:** Permite uma análise rápida de distribuição de riscos por projeto, sem necessidade de alterar filtros externos.

### 2. Slider e Linha de Mediana no Gráfico "Evolução de Ocorrências"

- **Descrição:** O gráfico de linha agora possui um **slider** para alternar entre visualização por **Severidade** e por **Status**. Em ambos os modos, é exibida uma linha de **mediana** (média móvel do total de ocorrências) calculada a partir dos últimos 3 pontos.
- **Comportamento:**
  - No modo **Severidade**: são plotadas linhas individuais para `critical`, `high`, `medium` e `low`, com pontos marcantes por data.
  - No modo **Status**: são plotadas linhas individuais para `open`, `recurring`, `resolved` e `wontFix`, com pontos marcantes por data.
  - A linha de **Mediana (Total)** é sempre exibida como uma linha tracejada cinza, representando a tendência suavizada do volume total.
- **Estilo visual:**
  - **Linhas principais:** cores padrão de severidade/status, com pontos preenchidos.
  - **Mediana:** Linha tracejada cinza (`#8E8E93`) sem pontos.
- **Benefício:** Permite uma visão clara da evolução de cada categoria, além de uma referência de tendência geral.

### 3. Filtro Interativo no Gráfico "Distribuição por Categoria"

- **Descrição:** Ao clicar em uma fatia do gráfico de pizza, o sistema adiciona automaticamente `AND category:"<categoria_clicada>"` à consulta DBQL atual.
- **Interação:**
  - Um botão **"Voltar"** (com ícone de X) aparece abaixo do gráfico, permitindo remover o filtro e restaurar a consulta original.
  - O clique no gráfico modifica a barra de busca DBQL e reexecuta a consulta de estatísticas.
- **Benefício:** Reduz drasticamente o tempo de investigação, permitindo drill-down direto do gráfico para a listagem filtrada.

### 4. Expandir Gráficos (Tela Cheia)

- **Descrição:** Cada card de gráfico possui um ícone de **expandir** (canto superior direito) que abre um modal com o gráfico em tamanho maior, ocupando a maior parte da tela.
- **Comportamento:**
  - O modal possui um botão de fechar (X) e um fundo escurecido com blur.
  - O gráfico expandido mantém todas as interações (cliques, sliders, etc.).
- **Benefício:** Permite uma visualização detalhada dos dados sem sair da página, melhorando a legibilidade em telas menores.

## 🛠 Detalhes de Implementação

### Backend (API)

#### `app/api/stats/route.ts`

- **Pipeline `projectPipeline`** foi alterado para agrupar os issues por projeto e também calcular contagens por `severity` e `status`.
- **Nova resposta:** `projectTotals` agora retorna um array de objetos com a seguinte estrutura:

```json
[
  {
    "label": "Nome do Projeto",
    "total": 123,
    "severity": { "critical": 1, "high": 20, "medium": 80, "low": 22 },
    "status": { "open": 50, "recurring": 10, "resolved": 60, "wontFix": 3 }
  }
]
```

- **Novo campo `chartData`**: cada ponto diário agora inclui contagens por severidade e por status, além do total. Exemplo:

```json
{
  "label": "2026-08-20",
  "critical": 0,
  "high": 50,
  "medium": 10,
  "low": 0,
  "total": 60,
  "open": 20,
  "recurring": 5,
  "resolved": 30,
  "wontFix": 5
}
```

- Nenhuma alteração foi feita nos pipelines de KPI ou categoria, exceto a reutilização da lógica de filtro DBQL já existente.

### Frontend

#### `lib/types.ts`

- Adicionadas as interfaces `DailyStats` e `StatsData` para tipar os dados retornados pela API:

```typescript
export interface DailyStats {
  label: string;
  critical: number;
  high: number;
  medium: number;
  low: number;
  total: number;
  open: number;
  recurring: number;
  resolved: number;
  wontFix: number;
}

export interface StatsData {
  kpi: { total: number; accepted: number; resolved: number; recurring: number; wontFix: number };
  severityTotals: Record<string, number>;
  categoryTotals: { label: string; value: number }[];
  projectTotals: {
    label: string;
    value: number;
    status?: Record<string, number>;
    severity?: Record<string, number>;
  }[];
  chartData: DailyStats[];
}
```

#### `components/Charts.tsx`

- **Novas props aceitas:**
  - `datasets?: any[]` – suporta múltiplos datasets (usado no gráfico de evolução e barras empilhadas).
  - `labels?: string[]` – rótulos do eixo X quando os datasets não os possuem.
  - `type?: 'bar' | 'line' | 'pie' | 'stacked-bar' | 'project-detail'` – tipos suportados.
  - `onSliceClick?: (label: string) => void` – callback chamado ao clicar em uma fatia do gráfico de pizza.
- **Lógica do gráfico de projetos (`type="stacked-bar"`):**
  - Constrói múltiplos datasets (um para cada categoria de status ou severidade) e os empilha (`stack: 'stack0'`).
  - Aplica cores mapeadas de acordo com o modo ativo (controlado pelo `page.tsx`).
- **Lógica do gráfico de linha:**
  - Aceita múltiplos datasets (para linhas por severidade/status) e uma linha adicional para a mediana.
  - As linhas suportam `borderDash` para diferenciação.
- **Interatividade do gráfico de pizza:**
  - O `onClick` verifica se o clique ocorreu sobre um elemento e, se sim, chama `onSliceClick` com o label correspondente.
  - Adicionado `cursor: pointer` via `onHover`.

#### `app/stats/page.tsx`

- **Novos estados:**
  - `projectViewMode: 'status' | 'severity'` (default `'status'`).
  - `evolutionViewMode: 'severity' | 'status'` (default `'severity'`).
  - `lastCategory: string | null` para armazenar a categoria clicada.
  - `expandedChart: string | null` para controlar o modal de expansão.
- **Funções implementadas:**
  - `handleSliceClick(category)` – adiciona `AND category:"..."` à `searchQuery` atual.
  - `clearCategoryFilter()` – remove o filtro de categoria da consulta e restaura a busca original.
  - `movingAverage(values, windowSize)` – calcula a média móvel para a linha de mediana.
- **Renderização:**
  - O card "Total por Projeto" inclui um **slider customizado** (não apenas dois botões) para alternância.
  - O card "Evolução" também inclui um **slider** para alternar entre Severidade e Status.
  - O card "Distribuição por Categoria" exibe um botão **"Voltar"** condicional quando um filtro está ativo.
  - Todos os cards possuem um **botão de expandir** que abre um modal.
- **Cálculo de tendências:**
  - A linha de **mediana** é calculada usando média móvel de 3 dias sobre o total diário.
  - A **projeção futura** não está incluída nesta versão (conforme especificado para simplificar a interpretação).

## ⚠️ Considerações e Limitações ( Sugestões de Backlog )

- **Média móvel:** A mediana é calculada com janela de 3 dias, o que pode suavizar demais picos em datasets com poucos pontos. Para datasets maiores, recomenda-se ajustar a janela.
- **Filtro por categoria:** O filtro é adicionado como `AND category:"..."`. Se a busca original já contiver um filtro de categoria, o novo filtro sobrescreverá o anterior. Uma melhoria futura seria usar `OR` se a intenção for incluir múltiplas categorias.
- **Performance:** O cálculo da média móvel é feito no client-side e é leve. A agregação de projetos com múltiplos campos pode aumentar levemente o tempo de resposta da API, mas permanece dentro dos limites aceitáveis para datasets típicos.
